# Safety Net ของทีม Campus Eats (ตัวอย่างที่กรอกครบ — จากเฉลย Lab12B)

## 1. ฟังก์ชันที่เลือกทดสอบ
- ฟังก์ชัน: `calculate_discount(total, tier, promo_code)` — อยู่ไฟล์ `src/calc.py`
- ฟังก์ชันเสริม: `calculate_payable` (ยอดสุทธิ) และ `validate_promo_code` (ตรวจรูปแบบโค้ด)
- เหตุผลที่เลือก: เป็น business logic เรื่องเงินโดยตรง มีกิ่งเงื่อนไขให้ทดสอบหลายเส้นทาง (tier + promo)
  และไม่พึ่ง DB/API → เขียนเทสต์ได้เร็วและเสถียร

## 2. เทสต์ที่เขียน (8 ตัว — เกินเกณฑ์ขั้นต่ำ 5)
| # | ชื่อเทสต์ | ประเภท | ยืนยันอะไร |

| 1 | test_vip_gets_15_percent | happy | VIP 1000 → ส่วนลด 150 |

## 3. Coverage (ผลรันจริง)

- **ตีความ:** ครอบคลุมทุกเส้นทางของ `calculate_discount` (tier vip/member/อื่นๆ × มี/ไม่มี promo)
  และทุกกิ่งที่ raise ValueError ของ `validate_promo_code`
- **ส่วนที่ยังไม่ครอบคลุม:** ไม่มีใน `src/` — แต่ยังไม่มีเทสต์ระดับ Integration (ชั้นถัดไปของ Pyramid เป็นงาน Sprint ถัดไป)
- **ยอมรับความเสี่ยงได้เพราะ:** ฟังก์ชันเป็น pure function ไม่มี side effect ภายนอก

## 4. CI block อะไรบ้าง
- `lint` (ruff): รูปแบบโค้ด — import ไม่ได้ใช้ / import เรียงผิด = แดง
- `test` (pytest): เทสต์ทั้ง 8 + coverage (รันบน ubuntu-latest Python 3.12)
- **Branch Protection:** `main` ต้องผ่าน `lint` + `test` และต้องมี PR + review ก่อน merge
- **หลักฐาน "Merging is blocked":** แคปหน้า PR ตอนที่ปุ่ม merge เป็นสีเทา (ทำตามขั้น 5.8 ของใบงาน)
  เก็บไว้ที่ `docs/` หรือแนบในคอมเมนต์ PR
