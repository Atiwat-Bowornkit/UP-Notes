# 📖 Scenarios Document — UP-Notes

เอกสารแสดง **Scenarios** รูปแบบเรื่องเล่า (Narrative Storytelling) จำลองสถานการณ์การใช้งานระบบ **UP-Notes** ของแต่ละ Persona ครอบคลุมทั้ง Happy Path และ Edge Cases

---

## 1. Scenarios สำหรับ Persona 1: Kankluay (Student / Power User)

### Scenario 1.1: การค้นหาและดาวน์โหลดชีทสรุปวิชาอัลกอริทึมก่อนสอบ Midterm (Happy Path)
* **Persona:** Kankluay (ณัฐนนท์)
* **Objective:** ค้นหาชีทสรุปวิชา Algorithm Design (225211) ที่ได้รับการยอมรับสูงเพื่อเตรียมสอบในคืนนี้
* **Narrative & Action Sequence:**
  1. ก้านกล้วยนั่งอยู่ที่ร้านกาแฟหน้า มพ. เหลือเวลาอีก 8 ชั่วโมงก่อนสอบวิชา Algorithm Design เขาเปิดเว็บ UP-Notes บนโน้ตบุ๊ก
  2. เขาสืบค้นด้วยรหัสวิชา `225211` ในช่องค้นหาหน้าแรก
  3. ระบบแสดงรายการโน้ตย่อที่ตรงกับวิชานี้ โดยก้านกล้วยเลือกรองรับการจัดเรียงตาม "จำนวนไลก์สูงสุด"
  4. ก้านกล้วยกดคลิกที่โน้ตย่อ "สรุปสอบกลางภาค Algo — Graph & Dynamic Programming" เพื่อพรีวิวดูตัวอย่างเอกสาร 3 หน้าแรก
  5. เมื่อเห็นว่าลายมืออ่านง่าย มีแผนภาพชัดเจน ก้านกล้วยกดปุ่ม "ดาวน์โหลด PDF"
* **ปัญหา/Edge Case ที่อาจพบ:** สัญญาณ Wi-Fi ร้านกาแฟช้า ทำให้การโหลดพรีวิวเอกสารขนาดใหญ่ค้างชั่วขณะ
* **ผลลัพธ์ที่หวัง:** ระบบแสดงตัวอย่างหน้าพรีวิวขนาดเบา (Thumbnail/Optimized PDF) ได้อย่างรวดเร็ว พร้อมปุ่มดาวน์โหลดไฟล์ PDF ฉบับเต็มได้สำเร็จในเวลาไม่เกิน 3 วินาที

### Scenario 1.2: การอัปโหลดสรุปบทเรียนวิชา Software Engineering เพื่อแบ่งปันให้เพื่อน (Happy Path)
* **Persona:** Kankluay (ณัฐนนท์)
* **Objective:** อัปโหลดไฟล์สรุปวิชา SE ที่ตนเองสแกนไว้ขึ้นระบบ พร้อมใส่แท็กรายละเอียด
* **Narrative & Action Sequence:**
  1. ก้านกล้วยต้องการอัปโหลดสรุปวิชา SE (225311) ที่เขาจัดทำขึ้นเองเพื่อแบ่งปันให้เพื่อนในเอก
  2. เขากดปุ่ม "อัปโหลดโน้ตย่อ" บนแถบเมนูหลัก และเข้าสู่หน้าฟอร์ม
  3. ก้านกล้วยกรอกชื่อเรื่อง "สรุปย่อ SE บทที่ 1-3 (Agile & Requirements)", เลือกรหัสวิชา `225311`, เลือกหมวดหมู่ `วิชาเอกบังคับ` และลากไฟล์ `SE_Summary_Ch1-3.pdf` วางลงในช่องอัปโหลด
  4. ระบบทำการตรวจสอบไฟล์ และก้านกล้วยกดปุ่ม "เผยแพร่โน้ตย่อ"
* **ปัญหา/Edge Case ที่อาจพบ:** พยายามอัปโหลดไฟล์ขนาดเกิน 15MB หรือไฟล์รูปแบบอื่นที่ไม่ใช่ PDF/PNG
* **ผลลัพธ์ที่หวัง:** ระบบแจ้งเตือน Error ชัดเจนว่า "รองรับเฉพาะไฟล์ PDF, PNG, JPG ขนาดไม่เกิน 10MB" พร้อมให้ผู้ใช้ย่อขนาดไฟล์ก่อนกดส่งอีกครั้ง

### Scenario 1.3: การแก้ไขข้อมูลโน้ตย่อที่อัปโหลดไปแล้วเมื่อพบคำผิด (Edge Case Path)
* **Persona:** Kankluay (ณัฐนนท์)
* **Objective:** แก้ไขชื่อเรื่องและคำอธิบายโน้ตย่อของตนเองเนื่องจากพิมพ์รหัสวิชาผิด
* **Narrative & Action Sequence:**
  1. หลังอัปโหลดโน้ตย่อไปแล้ว 10 นาที เพื่อนในแชตแจ้งก้านกล้วยว่าระบุรหัสวิชาผิดจาก `225311` เป็น `225310`
  2. ก้านกล้วยเข้าไปที่หน้า "แดชบอร์ดโน้ตของฉัน" (My Uploads)
  3. เขากดปุ่ม "แก้ไข" ที่การ์ดโน้ตย่อรายการนั้น และทำการแก้รหัสวิชาให้ถูกต้อง
  4. ก้านกล้วยกด "บันทึกการเปลี่ยนแปลง"
* **ปัญหา/Edge Case ที่อาจพบ:** ผู้ใช้กดปุ่มแก้ไขพร้อมกันหลายครั้ง หรือพยายามแก้ไขไฟล์ของผู้อื่น
* **ผลลัพธ์ที่หวัง:** ระบบป้องกันไม่ให้แก้ไขโน้ตย่อของสมาชิกคนอื่น (Unauthorized Edit) และอัปเดตข้อมูลบนหน้าเว็บทันทีเมื่อกดบันทึกสำเร็จ

## 2. Scenarios สำหรับ Persona 2: Mint (Student / Mobile On-the-go Learner)

### Scenario 2.1: การอ่านพรีวิวชีทสรุปวิชา GE บนรถขบมหาวิทยาลัยผ่านสมาร์ตโฟน (Happy Path)
* **Persona:** Mint (ณัฐมล)
* **Objective:** ค้นหาและพรีวิวอ่านชีทสรุปวิชา GE ภาษาไทยบนสมาร์ตโฟนระหว่างเดินทางไปเรียน
* **Narrative & Action Sequence:**
  1. มิ้นท์ขึ้นรถขบประจำทางของมหาวิทยาลัยพะเยาเพื่อเดินทางไปเรียนตึก ICT เธอนึกขึ้นได้ว่ามีควิซวิชา GE
  2. มิ้นท์หยิบสมาร์ตโฟนขึ้นมา เปิดเบราว์เซอร์เข้า UP-Notes
  3. เธอพิมพ์คำว่า "GE Thai" ในช่องค้นหา และเลือกรายการสรุปย่อฉบับอ่านจบใน 5 นาที
  4. หน้าจอโทรศัพท์แสดงผลพรีวิวชีทสรุปในรูปแบบที่ฟิตพอดีกับหน้าจอมือถือ (Responsive Mobile View)
  5. มิ้นท์ใช้นิ้วปัดเลื่อนอ่านเนื้อหาพรีวิวได้ทันทีโดยไม่ต้องโหลดไฟล์ฉบับเต็มลงเครื่อง
* **ปัญหา/Edge Case ที่อาจพบ:** สัญญาณมือถือขาดหายชั่วขณะระหว่างรถขบวิ่งผ่านจุดอับสัญญาณ
* **ผลลัพธ์ที่หวัง:** ระบบมี Caching แสดงผลหน้าพรีวิวที่โหลดไว้แล้วได้ต่อเนื่องโดยไม่เด้งหลุด

### Scenario 2.2: การกดดาวน์โหลดไฟล์ออฟไลน์และกดไลก์ขอบคุณผู้เขียน (Happy Path)
* **Persona:** Mint (ณัฐมล)
* **Objective:** ดาวน์โหลดไฟล์สรุปเก็บไว้ในแอปไฟล์ของมือถือ และกดปุ่มไลก์ให้กำลังใจเจ้าของสรุป
* **Narrative & Action Sequence:**
  1. หลังอ่านพรีวิวสรุปวิชา GE แล้ว มิ้นท์รู้สึกว่าสรุปนี้เขียนได้เข้าใจง่ายมาก
  2. เธอกดปุ่ม "กดไลก์ (Like)" ที่หน้าโน้ตย่อ จำนวนไลก์เพิ่มขึ้นทันทีจาก 45 เป็น 46
  3. มิ้นท์กดปุ่ม "ดาวน์โหลดไฟล์" เพื่อเก็บไว้ในเครื่องโทรศัพท์สำหรับอ่านต่อในห้องเรียน
* **ปัญหา/Edge Case ที่อาจพบ:** มิ้นท์ยังไม่ได้เข้าสู่ระบบเมื่อกดปุ่มไลก์
* **ผลลัพธ์ที่หวัง:** ระบบแสดง Pop-up ให้ล็อกอินสั้นๆ ผ่านระบบ หรือบันทึกสถานะไลก์ให้อัตโนมัติเมื่อเข้าสู่ระบบสำเร็จ

### Scenario 2.3: การค้นหาชีทสรุปในรายวิชาที่ไม่เคยมีใครอัปโหลดมาก่อน (Edge Case Path)
* **Persona:** Mint (ณัฐมล)
* **Objective:** ค้นหาสรุปวิชาเลือกใหม่ที่เพิ่งเปิดสอนในปีการศึกษานี้
* **Narrative & Action Sequence:**
  1. มิ้นท์พิมพ์รหัสวิชาเลือกใหม่ `225199` ในช่องค้นหา
  2. ระบบทำการค้นหาในฐานข้อมูลและพบว่ายังไม่มีผู้ใช้อัปโหลดสรุปในรายวิชานี้
* **ปัญหา/Edge Case ที่อาจพบ:** หน้าเว็บแสดงผลว่างเปล่า (Blank Page) ทำให้ผู้ใช้คิดว่าระบบพัง
* **ผลลัพธ์ที่หวัง:** ระบบแสดงหน้าจอ Empty State ที่เป็นมิตร พร้อมข้อความ "ยังไม่มีโน้ตย่อในวิชานี้ เป็นคนแรกที่แบ่งปันสรุปวิชานี้กันเถอะ!" พร้อมปุ่มทางลัดไปยังหน้าอัปโหลด

## 3. Scenarios สำหรับ Persona 3: Dr. Nat (Instructor / Course Moderator)

### Scenario 3.1: การเข้าดูและตรวจสอบความถูกต้องของสรุปวิชาที่ตนเองสอน (Happy Path)
* **Persona:** Dr. Nat (ดร. ณัฐวุฒิ)
* **Objective:** ตรวจสอบชีทสรุปยอดนิยมวิชา Software Engineering เพื่อเช็กความเข้าใจของนิสิตก่อนสอบ
* **Narrative & Action Sequence:**
  1. อาจารย์นัทเปิด iPad Pro เข้าเว็บ UP-Notes ก่อนถึงสัปดาห์สอบกลางภาค
  2. เขาเลือกกรองค้นหาตามรหัสวิชา `225311` (Software Engineering) และจัดเรียงตาม "ยอดนิยมสูงสุด"
  3. อาจารย์นัทเปิดอ่านพรีวิวชีทสรุปที่มีนิสิตกดไลก์มากที่สุด เพื่อตรวจดูว่าสูตรและคำอธิบายทฤษฎี Agile/Scrum ถูกต้องหรือไม่
* **ปัญหา/Edge Case ที่อาจพบ:** ไฟล์พรีวิวขนาดความละเอียดต่ำเกินไปจนอ่านตัวหนังสือบน iPad ไม่ชัด
* **ผลลัพธ์ที่หวัง:** เอกสารพรีวิวแสดงความคมชัดระดับ HD รองรับการขยายภาพ (Zoom-in) บน iPad ได้อย่างชัดเจน

### Scenario 3.2: การรายงาน (Report) สรุปที่มีข้อมูลผิดพลาดหรือเฉลยข้อสอบเก่าละเมิดลิขสิทธิ์ (Edge Case Path)
* **Persona:** Dr. Nat (ดร. ณัฐวุฒิ)
* **Objective:** รายงานโน้ตย่อที่มีการแนบไฟล์ข้อสอบจริงย้อนหลังซึ่งไม่อนุญาตให้เผยแพร่
* **Narrative & Action Sequence:**
  1. อาจารย์นัทพบโน้ตย่อรายการหนึ่งที่มีการนำไฟล์ข้อสอบจริงกลางภาคของปีที่แล้วมาโพสต์ลงระบบ
  2. เขากดปุ่ม "รายงานปัญหา (Report Note)" ที่มุมขวาของหน้าเอกสาร
  3. เขาเลือกสาเหตุ "ละเมิดลิขสิทธิ์ / ข้อสอบไม่อนุญาตให้เผยแพร่" และพิมพ์รายละเอียดเพิ่มเติม
  4. อาจารย์นัทกดส่งรายงานปัญหา
* **ปัญหา/Edge Case ที่อาจพบ:** การรายงานถูกส่งไปโดยไม่มีการบันทึก Log หรือไม่มีการแจ้งเตือนผู้ดูแลระบบ
* **ผลลัพธ์ที่หวัง:** ระบบบันทึกการรายงาน ซ่อนโน้ตย่อชั่วคราวเพื่อรอการตรวจสอบ (Pending Moderation) และส่งการแจ้งเตือนไปยังผู้ดูแลระบบทันที
