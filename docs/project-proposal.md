# 📌 Project Proposal: UP-Notes

## 1. Theme
**Tools for Modern Learners (เครื่องมือสำหรับผู้เรียนยุคใหม่)**
* **เหตุผลในการเลือก:** นิสิตมหาวิทยาลัยพะเยาจำนวนมากประสบปัญหาขาดแคลนสรุปบทเรียนย่อที่เข้าใจง่ายสำหรับเตรียมสอบ และโน้ตย่อส่วนใหญ่กระจัดกระจายตามโซเชียลมีเดียส่วนตัว ทีมเราจึงเลือก Theme นี้เพื่อสร้างแพลตฟอร์มศูนย์กลางในการรวบรวม แบ่งปัน และค้นหาโน้ตย่อการเรียนที่ตรงกับรายวิชาของมหาวิทยาลัยพะเยาโดยเฉพาะ ช่วยส่งเสริมวัฒนธรรมการแบ่งปันความรู้และเพิ่มประสิทธิภาพในการเรียนรู้ของนิสิต

---

## 2. Project Name
**UP-Notes** *(คลังปันสรุปบทเรียนและโน้ตย่อสำหรับนิสิต มหาวิทยาลัยพะเยา)*

---

## 3. Persona หลัก
* **ชื่อ:** นาย ก้านกล้วย (นิสิตสายลุย สรุปเข้มก่อนสอบ)
* **บริบท:** นิสิตชั้นปีที่ 3 สาขาวิทยาการคอมพิวเตอร์ มหาวิทยาลัยพะเยา ที่มีตารางเรียนและกิจกรรมแน่นในแต่ละสัปดาห์ เมื่อใกล้ถึงช่วงสอบทบทวนบทเรียน มักจะทบทวนเนื้อหาไม่ทันและต้องการค้นหาโน้ตย่อสรุปบทเรียนที่มีคุณภาพจากรุ่นพี่หรือเพื่อนร่วมรายวิชาเดียวกัน ก้านกล้วยต้องการระบบที่จัดหมวดหมู่โน้ตตามรหัสวิชา สามารถค้นหาตามคีย์เวิร์ดได้อย่างรวดเร็ว พรีวิวไฟล์เอกสารได้ก่อนดาวน์โหลด และสามารถกดไลก์ส่งต่อกำลังใจให้ผู้เขียนสรุปได้

---

## 4. Value Proposition
* **ปัญหาที่แก้ไข:** ปัญหาเนื้อหาสรุปบทเรียนกระจัดกระจาย ขาดความน่าเชื่อถือ และไม่มีระบบค้นหาตามรหัสวิชาของมหาวิทยาลัยพะเยา
* **คุณค่าที่ผู้ใช้ได้รับ:** UP-Notes มอบแพลตฟอร์มศูนย์กลางที่รวบรวมโน้ตย่อคุณภาพ มีระบบจัดหมวดหมู่ตามรหัสวิชา/ปีการศึกษา สามารถค้นหาและพรีวิวไฟล์ได้อย่างรวดเร็ว ช่วยให้นิสิตประหยัดเวลาเตรียมสอบ และเปิดโอกาสให้ผู้สรุปบทเรียนสร้างโปรไฟล์แบ่งปันความรู้ร่วมกันในสังคมการศึกษา

## 6. Risks & Assumptions

### สมมติฐานหลัก (Key Assumptions)
1. นิสิตมหาวิทยาลัยพะเยายินดีที่จะแบ่งปันโน้ตย่อสรุปบทเรียนของตนเองลงแพลตฟอร์มสาธารณะ
2. รูปแบบไฟล์ PDF และรูปภาพโน้ตย่อที่อัปโหลดมีขนาดไม่เกินขีดจำกัดของ Object Storage (Supabase Storage)

### ความเสี่ยงและแนวทางรับมือ (Risks & Mitigation Strategies)
1. **ความเสี่ยงด้านเนื้อหาละเมิดลิขสิทธิ์หรือข้อสอบเก่า (Copyright/Policy Violation Risk):**
   * *แนวทางรับมือ:* กำหนดข้อตกลงการใช้งาน (Terms of Service) ชัดเจน ห้ามอัปโหลดข้อสอบจริง และมีระบบแจ้งลบเนื้อหาที่ไม่เหมาะสมโดยผู้ดูแลระบบ (Admin)
2. **ความเสี่ยงด้านประสิทธิภาพระบบคลาวด์และ Storage (Storage Performance & Security Risk):**
   * *แนวทางรับมือ:* จำกัดขนาดไฟล์อัปโหลดไม่เกิน 10MB ต่อไฟล์ และใช้ Supabase Storage พร้อมตั้งค่า Row Level Security (RLS) เพื่อควบคุมสิทธิ์การเข้าถึงไฟล์ข้อมูลอย่างปลอดภัย
