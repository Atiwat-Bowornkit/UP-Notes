## 4. Broken Window ที่เคยเจอ
* **(1) Window คืออะไร:** การเขียนโค้ดแบบ Hardcode ค่า URL หรือ API Key ลงในซอร์สโค้ดตรงๆ แทนที่จะใช้ Environment Variables (`.env`) รวมถึงการปิด Silent Error Handling ด้วย `try { ... } catch (e) {}` โดยไม่ทำ Logging
* **(2) ผลกระทบที่เกิดขึ้น:** เมื่อต้องเปลี่ยนสภาพแวดล้อมจาก Local Dev ไปยัง Staging Server ระบบทำงานไม่ได้และไม่ทิ้ง Log แจ้งเตือนข้อผิดพลาดใดๆ ทำให้สมาชิกในทีมต้องเสียเวลาหาข้อผิดพลาดร่วมกันเป็นเวลานานเนื่องจากไม่ทราบว่าฟังก์ชันหยุดทำงานที่จุดใด
* **(3) ถ้าแก้ไขทันทีจะป้องกันอะไร:** การแยก Configuration ออกมาอยู่ใน `.env` และเขียนระบบ Log บันทึก Error ที่ชัดเจนตั้งแต่เริ่มต้น จะช่วยป้องกันปัญหาความปลอดภัย (Secret Leak) ป้องกันความสับสนเมื่อเปลี่ยน Deployment Environment และทำให้ระบุจุดบกพร่องของระบบได้ทันทีเมื่อเกิดเหตุขัดข้อง
