## 4. Broken Window ที่เคยเจอ
* **(1) Window คืออะไร:** ในโปรเจกต์เว็บแอปพลิเคชันก่อนหน้านี้ ผมเคยปล่อยปละละเลยการระบุ Type ใน TypeScript โดยใช้ `any` เพื่อให้โค้ดผ่านการคอมไพล์อย่างรวดเร็ว รวมถึงเพิกเฉยต่อ Warning เล็กๆ น้อยๆ จาก Linter
* **(2) ผลกระทบที่เกิดขึ้น:** เมื่อระบบมีขนาดใหญ่ขึ้นและมีสมาชิกในทีมเข้ามาพัฒนาต่อ การใช้ `any` ทำให้ Intellisense และ Autocomplete ไม่ทำงาน ส่งผลให้เกิด Runtime TypeError โดยไม่คาดคิดในส่วนข้อมูลที่ซ้อนกัน และต้องเสียเวลาหลายวันในการไล่สแต็กเทรซเพื่อค้นหาจุดที่ส่งค่า Null/Undefined เข้ามา
* **(3) ถ้าแก้ไขทันทีจะป้องกันอะไร:** หากแก้ไขและระบุ Interface/Type ให้ชัดเจนตั้งแต่บรรทัดแรกที่เขียน จะช่วยให้ TypeScript Compiler ดักจับ Type Mismatch ได้ตั้งแต่ขณะพัฒนา ป้องกัน Runtime Crash บน Production ลดหนี้ทางเทคนิค (Technical Debt) และทำให้เพื่อนในทีมเข้าใจโครงสร้างข้อมูลได้ทันทีโดยไม่ต้องคาดเดา
